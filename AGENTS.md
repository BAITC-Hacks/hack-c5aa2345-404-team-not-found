# Инструкции для участников и Codex

## Цель

SAMRUK KAZYNA: локальное протоколирование русских, казахских и смешанных совещаний для HackAlem. Текущий клиентский результат — Windows-приложение EXE. Backend и модели работают на том же компьютере либо на сервере внутри локальной сети.

## Перед началом

Прочитай README.md, docs/team-workflow.md, docs/api-contract.md и задание своей роли в docs/team-prompts.md. Используй актуальную документацию официального командного репозитория. При незавершённых изменениях сначала безопасно сохрани работу; не выполняй reset, clean или принудительную смену ветки.

## Три роли и границы

- **Backend / Medet:** backend API, схемы, доменные модели, очередь, хранение, объединение timestamps, экспорт, интеграция. Владелец общих README.md, ROADMAP.md, .env.example, .gitignore, docs/api-contract.md и базовых Python-зависимостей.
- **Local AI:** scripts/local-ai/, docs/local-ai/, backend/requirements-ai.txt, backend/app/services/{stt,diarization,llm}/local.py и backend/tests/local_ai/. Существующие base.py, placeholder.py, __init__.py и общие модели не менять без согласования с backend.
- **Windows Desktop:** frontend/, .streamlit/, desktop/, docs/desktop/, docs/screenshots/. Сначала изучить уже опубликованный Streamlit UI в codex/streamlit-frontend и сохранить полезные наработки. Упаковка в EXE — в desktop/; зависимости UI — внутри frontend/ или desktop/.

Изменения общих файлов предлагает их владельцу. Несогласованный контракт не менять. Блокер вне своей зоны описать в документе передачи работы, продолжая независимые задачи.

## Git

- Официальный репозиторий: https://github.com/BAITC-Hacks/hack-c5aa2345-404-team-not-found.
- Проверяй URL remote: его имя может отличаться у участников. Не отправляй работу в старый личный репозиторий Derek.
- Ветки: codex/backend, codex/local-ai-setup, codex/desktop-app. Основную ветку объединяет backend-координатор после проверки совместимости. Если работа над прежним Android-клиентом уже началась, сохрани её ветку и перенеси подходящие наработки в desktop-задачу без удаления истории.
- Сохраняй историю команды и чужие изменения. Не используй force push и не переноси материалы прежнего проекта, созданные до хакатона.
- Коммит и push выполняй в пределах разрешения владельца сессии; роль-промпты разрешают отправку только своей рабочей ветки. Слияние в main требует команды координатора.
- Модели, окружения, .env, токены, записи, результаты встреч и ключи подписи не добавлять в Git. EXE передавать как артефакт; публикацию Release согласовать отдельно.

## Работа и проверка

- Установки допустимы в рамках явно выданного задания своей роли; прежний запрет подготовительного этапа не блокирует уже разрешённую установку AI или Desktop-окружения.
- При установке проверяй текущие официальные требования и фиксируй воспроизводимые версии. Для Community-1 нужен pyannote.audio 4.x; прежнее ограничение <4.0 не применять к нему.
- Нельзя передавать аудио, транскрипты и производные чувствительные данные в облачные AI API, MCP или другие внешние сервисы. Документацию можно читать онлайн без передачи этих данных.
- Каждый интерфейс и placeholder отличать от реально работающей функции. Демонстрационные данные показывать только в явно включённом деморежиме; ошибки сервера не маскировать ими.
- Проверки запускай по своей задаче. В итоговом отчёте перечисляй выполненные проверки и ограничения; не заявляй успешный запуск без наблюдаемого результата.
- README обновляй вместе с изменениями: жюри должны понять проблему, технологии, запуск и шаги проверки. Командные требования организаторов — docs/hackathon-checklist.md.
