# План развития SAMRUK KAZYNA

## Реализовано в текущем main

- Нативный WinForms-клиент, настройки backend, API-клиент и явное RU/KK-демо.
- Сборка одного EXE, локальный DOCX, отчёт проверок и скриншоты.
- FastAPI API: загрузка, последовательная очередь, SQLite, статусы и Result.
- Нормализация mono PCM16 WAV 16 kHz для обоих адаптеров, лимиты и ошибки.
- Подключение адаптеров, объединение timestamps с UNRESOLVED при неоднозначности,
  разбиение текста без усечения, валидация источников и неизвестные значения null.
- Серверные DOCX/PDF с RU/KK; 22 backend-проверки и 10 native→real API проверок
  с синтетическими моделями.
- Локальные адаптеры Whisper, Community-1 и Qwen3; отдельные измерения и тесты.
- Отчёт по записи 274,25 с и CLI воспроизводимой диагностики; 43 автономные
  проверки по отчёту команды. Полный реальный прогон новой версии CLI ещё нужен.
- Инструкции запуска, архитектура и сценарий жюри.

Связка клиент → API → worker → SQLite → экспорт проверена с синтетическими
моделями. Полный прогон на реальной записи и GPU требует этапа 1.

| Приоритет | Работа | Критерий завершения |
| --- | --- | --- |
| 1. Реальная проверка интеграции | Запустить готовый backend на ПК Local AI, обработать запись через EXE, проверить качество и экспорт | Реальные GPU-модели дают проверенный DOCX/PDF через действующий HTTP API |
| 2. Воспроизводимость | Второй Windows-ПК, серверное окружение, согласованный EXE-артефакт, offline-сценарий | Другой участник проходит инструкции без скрытых локальных файлов |
| 3. Качество RU/KK | Эталонные записи, WER/DER, полнота поручений, ошибочные имена/сроки | Опубликован обезличенный отчёт о метриках и ошибках |
| 4. Рабочий процесс | Редактирование и версии поручений, статусы, контроль дедлайнов | Согласован API, правки сохраняются и совпадают с экспортом |
| 5. Эксплуатация | Аутентификация, HTTPS, роли, retention, аудит, восстановление после сбоя | Проверен сценарий развёртывания и обращения с данными |
| 6. Дополнительные интеграции | Запись/коннекторы встреч, напоминания, календарь | Подтверждена польза и реализованы отдельные проверяемые интеграции |

Первый этап выполняет backend с участием Local AI и Desktop. Детали границ —
[team-workflow](docs/team-workflow.md), запуск — [backend-launch](docs/backend-launch.md),
исторические расхождения — [integration-notes](docs/integration-notes.md).

Особенность подхода — сочетание локальной обработки смешанной речи и поручений
с проверяемыми источниками. Уникальность относительно других продуктов не
измерялась. Масштабирование на несколько пользователей потребует развития текущей очереди,
контроля ресурсов и доступа; выполненные синтетические проверки этого не подтверждают.

Инструменты измерения прогресса: [проверки](docs/verification.md) и
[критерии сдачи](docs/hackathon-checklist.md). Автоматическое выставление баллов
или обещание экономического эффекта не используется.
