# SAMRUK KAZYNA

Локальная система протоколирования совещаний на русском, казахском и смешанном русско-казахском языке. Проект команды **404-team-not-found** для HackAlem.

## Какую проблему решаем

Секретари вручную составляют протоколы встреч: это занимает время, а поручения, сроки и ответственные могут потеряться или быть записаны неточно. SAMRUK KAZYNA должен преобразовывать запись встречи в проверяемый транскрипт, краткое резюме и список поручений с источниками.

**Целевой сценарий:** пользователь открывает Windows-приложение, выбирает аудио/видео, получает реплики говорящих, резюме и поручения, затем сохраняет протокол в DOCX/PDF. Имена и сроки, которых нет в записи, система не должна выдумывать.

## Приватность и размещение

Аудио, транскрипты и результаты обрабатываются внутри инфраструктуры пользователя. Облачные AI API не используются. После первоначальной загрузки моделей целевой пайплайн должен работать без интернета.

Первый Windows EXE будет содержать интерфейс и его runtime. Backend и модели запускаются отдельно:
- на том же компьютере: API `http://127.0.0.1:8000`;
- на другом компьютере в LAN: адрес сервера задаётся в настройках клиента.

Первую интеграцию проводим на компьютере участника Local AI. Установленный EXE не предполагает наличие Python, Node.js или ручного запуска UI-сервера у пользователя. В варианте PyInstaller клиентский Python runtime входит в сборку. Отдельное окружение backend и модели устанавливаются на стороне сервера и не входят в первый EXE.

## Технологии

| Слой | Технологии | Назначение |

| Windows-клиент | Streamlit UI в отдельной ветке; план упаковки — pywebview + PyInstaller | сохранить текущий интерфейс и получить Windows EXE; сборку ещё нужно проверить |

| Анализ, план | локальная Qwen3 через Ollama / llama.cpp | резюме и поручения |
| Хранение и экспорт, план | SQLite, python-docx, ReportLab | встречи, DOCX и PDF |

Размер LLM, режим GPU и версии для полной установки фиксируются после проверки железа. Все planned-компоненты до интеграции считаются неподтверждёнными.

## Как запустить текущий каркас backend

Нужны Git, доступ к командному репозиторию и Python 3.11. Команды ниже для PowerShell, запускаются из корня репозитория. API-зависимости вынесены отдельно, поэтому этот запуск не требует скачивания моделей.

Если репозиторий ещё не склонирован:

```powershell
git clone https://github.com/BAITC-Hacks/hack-c5aa2345-404-team-not-found.git
cd hack-c5aa2345-404-team-not-found
```

Создать окружение и запустить сервер:

```powershell
py -3.11 -m venv backend/.venv
.\backend\.venv\Scripts\python.exe -m pip install -r backend/requirements-api.txt
.\backend\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Окно сервера оставьте открытым. Для остановки нажмите Ctrl+C. В Linux/macOS эквивалент — `python3.11 -m venv backend/.venv` и `backend/.venv/bin/python` вместо Windows-пути к Python.

Сейчас настройки каркаса заданы в `backend/app/core/config.py`; `.env.example` описывает будущую конфигурацию. Автоматическое чтение `.env` пока не реализовано. Полный `backend/requirements.txt` включает будущие AI-зависимости и не нужен для этой проверки.

## Как проверить текущую версию

Во втором PowerShell-окне:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health | ConvertTo-Json -Depth 4
curl.exe -i -X POST http://127.0.0.1:8000/api/meetings
```

Ожидаемое поведение:

1. `GET /health` возвращает HTTP 200, `status: "scaffold"`, `local_only: true` и список запланированных модулей.
2. По адресу `http://127.0.0.1:8000/docs` открывается Swagger с названием **SAMRUK KAZYNA Meeting Protocol API**.
3. `POST /api/meetings` возвращает HTTP 501 с пояснением, что обработка ещё не настроена. Файл не обрабатывается; это ожидаемая заглушка.
4. [Пример результата](samples/api/meeting-completed.json) показывает согласованные поля. Он синтетический и используется только для явно обозначенного деморежима UI.

Если сервер не отвечает, проверьте его окно и порт 8000. Если `py -3.11` не найден, установите Python 3.11 или укажите его абсолютный путь. Список в requirements пока задаёт диапазоны версий, а не проверенный lockfile.

**Проверка этого обновления:** сверены ссылки, JSON и синтаксис Python. Запуск HTTP-сервера здесь не проверен: FastAPI и Uvicorn в текущем окружении не установлены. Команда должна зафиксировать успешный запуск и точные версии перед сдачей.

## Как жюри проверят полное решение после интеграции

Это критерии приёмки, а не утверждение о готовности текущей версии:

1. Установить модели и запустить backend по проверенной инструкции участника Local AI.
2. Запустить предоставленный EXE и указать адрес backend.
3. Выбрать согласованную запись с двумя говорящими и русско-казахской речью.
4. Дождаться завершения обработки; проверить исходные слова, говорящих и временные метки.
5. Сверить поручения, ответственных и сроки с исходной записью. Неизвестные данные должны оставаться неизвестными.
6. Открыть DOCX и PDF, проверить содержание протокола.
7. Повторить обработку при отсутствии внешнего интернета после загрузки моделей, сохранив доступ к локальному backend.

Для реальных измерений нужны исходная запись с согласием участников и эталонная расшифровка. Время обработки, память, ошибки смешанной речи и ограничения должны быть записаны в отчёте. Подробный [чек-лист сдачи](docs/hackathon-checklist.md).

## Команда и структура

| Роль | Ветка | Ответственность |
| --- | --- | --- |
| Medet — backend | `codex/backend` | API, хранение, очередь, экспорт, интеграция и общий README |
| Local AI | `codex/local-ai-setup` | модели, локальное окружение, проверки и адаптеры |
| Windows Desktop | `codex/desktop-app` | интерфейс, API-клиент, EXE и скриншоты |

```text
backend/                 # текущий Python-каркас
  requirements-api.txt   # только зависимости для запуска API
  requirements.txt       # полный план зависимостей
samples/                 # синтетические примеры
docs/                    # архитектура, API, работа команды и задания
scripts/                 # место для локальных setup-скриптов
AGENTS.md                # правила для участников и Codex
```

Под упаковку Windows-клиента выделен будущий каталог `desktop/`; исходный UI находится в `frontend/` отдельной ветки; под AI-скрипты — `scripts/local-ai/`. Пока реализация клиента в main не добавлена. Возможность упаковки текущего UI проверяет Desktop-участник; переход на Electron требует согласования и не должен уничтожать уже сделанную работу.

Начните с [AGENTS.md](AGENTS.md), [архитектуры](docs/architecture.md), [правил работы](docs/team-workflow.md) и [промпта своей роли](docs/team-prompts.md). Этапы развития — [ROADMAP.md](ROADMAP.md). Каждый работает в своей ветке; объединение в main выполняет координатор после проверки совместимости.
