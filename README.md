# HackAlem — локальное протоколирование совещаний

Privacy-first система для автоматического протоколирования совещаний внутри инфраструктуры организации. Цель — сократить ручную работу секретаря, сохранить поручения, сроки и ответственных в проверяемой структуре.

## Проблема

Ручное ведение протоколов занимает время и повышает риск потерять поручение, исказить срок или неправильно определить ответственного.

## Подход

Пользователь выбирает аудио или видео совещания в Android-приложении. В целевой архитектуре приложение передаёт запись backend внутри локальной сети. Сервер локально создаёт транскрипт русской, казахской и смешанной речи, разделяет реплики по анонимным говорящим, формирует summary и поручения, а затем экспортирует итоговый протокол. Клиентский результат текущего этапа — устанавливаемый APK.

## Три участника — три зоны работы

| Роль | Задача | Рабочая ветка |
| --- | --- | --- |
| Medet — backend | API, хранение, очередь, интеграция моделей, экспорт | `codex/backend` |
| Local AI | окружение, локальные модели, проверки и адаптеры | `codex/local-ai-setup` |
| Android | мобильный интерфейс, API-клиент и APK | `codex/android-app` |

Перед началом прочитайте [AGENTS.md](AGENTS.md), [порядок командной работы](docs/team-workflow.md) и [API-контракт](docs/api-contract.md). Здесь находятся [два готовых промпта для друзей](docs/team-prompts.md). Каждый отправляет свою ветку; main объединяет координатор. Общий репозиторий не синхронизирует локальные изменения автоматически.

## Privacy-first / on-premise

Аудио и транскрипты не должны передаваться в облачные AI API. Целевая обработка выполняется локально: faster-whisper для STT, pyannote для diarization и локальная LLM через Ollama или llama.cpp. Модели и записи не хранятся в Git.

## Текущий статус: подготовительный каркас

**Уже подготовлено:**

- структура FastAPI backend;
- схемы транскрипта, реплик и поручений;
- абстрактные интерфейсы STT, diarization, local LLM и экспорта;
- placeholder-реализации, которые не загружают модели и не обращаются к внешним сервисам;
- примеры mixed ru/kk транскрипта и ожидаемого результата;
- конфигурационный шаблон и документация архитектуры.
- зоны ответственности трёх участников, целевой API-контракт и синтетический JSON для разработки APK.

**Ещё не реализовано:**

- обработка аудио/видео;
- faster-whisper, pyannote и локальная LLM;
- загрузка файлов и хранение результатов;
- DOCX/PDF экспорт;
- база данных, аутентификация, напоминания, Teams/Zoom/Google Meet, mobile и Docker.

В текущей версии репозитория AI pipeline и APK ещё не подтверждены работающими. Участник Local AI устанавливает модели на своём компьютере; результаты он зафиксирует в `docs/local-ai/handoff.md`. Участник Android передаст сборку и отчёт в `docs/mobile/handoff.md`.

## Предполагаемый стек

- Python 3.11, FastAPI, Pydantic, Uvicorn;
- FFmpeg для подготовки аудио;
- faster-whisper с Whisper large-v3 или large-v3-turbo;
- pyannote/speaker-diarization-community-1;
- Qwen3 через Ollama или llama.cpp;
- SQLite для MVP, PostgreSQL позднее;
- python-docx и PDF-библиотека для экспорта.
- Android-клиент: React Native + Expo + TypeScript; если участник уже начал мобильную реализацию на другом стеке, выбор согласуется до переноса кода.

## Структура

```text
backend/
  app/
    api/             # будущие HTTP-границы
    core/            # конфигурация и ошибки
    models/          # внутренние доменные модели
    schemas/         # API-схемы Pydantic
    services/        # контракты STT, diarization, LLM и экспорта
  tests/
  requirements.txt   # планируемые, но не установленные зависимости
samples/             # безопасные JSON-примеры без записей людей
docs/                # архитектура и принципы
scripts/             # место для будущих setup-скриптов
AGENTS.md            # правила работы трёх ролей
```

Для Android выделен будущий каталог `mobile/`; для AI-скриптов — `scripts/local-ai/`. Реализация этих частей ведётся в соответствующих ветках.

Подробнее: [docs/architecture.md](docs/architecture.md) и [ROADMAP.md](ROADMAP.md).

## Будущий локальный запуск

Конкретные команды появятся после проверки окружения участником Local AI. Для первой интеграции backend и модели будут работать на его компьютере; Android-клиент подключается к адресу backend в LAN. Разрешения на установку и задачи каждой роли описаны в [промптах](docs/team-prompts.md).

## APK и скриншоты

Готовой проверенной APK-сборки в этой версии ещё нет. После запуска на устройстве/эмуляторе добавим сюда реальные скриншоты из `docs/screenshots/`, инструкции установки, проверенный сценарий и ссылку на артефакт APK. Деморежим будет явно обозначен. APK, модели и ключи подписи не добавляются в историю Git.

## Roadmap

1. Параллельно подготовить локальные модели, backend API и Android UI по общему контракту.
2. Проверить STT, diarization и локальную LLM на согласованной русско-казахской записи.
3. Объединить адаптеры, очередь, хранение и DOCX/PDF экспорт в backend.
4. Подключить APK к backend в LAN и проверить весь пользовательский сценарий.
5. Добавить проверенные команды запуска, APK и реальные скриншоты в документацию.
