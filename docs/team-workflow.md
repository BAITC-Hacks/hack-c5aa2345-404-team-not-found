# Работа команды SAMRUK KAZYNA

## Ответственность

| Участник | Ветка | Результат | Изменяемые пути |
| --- | --- | --- | --- |
| Medet: backend и интеграция | `codex/backend` | API, очередь, хранение, объединение STT/diarization, DOCX/PDF | `backend/`, кроме файлов Local AI; общая документация и конфиги |
| Друг: Local AI | `codex/local-ai-setup` | проверенные модели и адаптеры | `scripts/local-ai/`, `docs/local-ai/`, `backend/requirements-ai.txt`, `backend/app/services/{stt,diarization,llm}/local.py`, `backend/tests/local_ai/` |
| Друг: Windows Desktop | `codex/desktop-app` | UI, API-клиент, Windows EXE | `frontend/`, `.streamlit/`, `desktop/`, `docs/desktop/`, `docs/screenshots/` |

Итоговый клиент — Windows EXE. Предыдущая Android/APK-задача заменена desktop-задачей. Уже созданный код сохраняется в прежней ветке; перенос подходящих наработок выполняется отдельно, без удаления чужой работы.

Обнаружена опубликованная ветка codex/streamlit-frontend. Сначала изучить её, не переписывать готовый интерфейс только ради смены платформы. Эта ветка содержит и backend-изменения: их интеграция требует участия Medet. См. [заметки о расхождениях API](integration-notes.md).

## Git и синхронизация

1. Проверь `git status`, текущую ветку и URL remote. Официальный репозиторий — BAITC-Hacks/hack-c5aa2345-404-team-not-found; имя remote у участников может различаться.
2. Выполни `git fetch <team-remote>`. Новую работу начинай в своей ветке от актуального main.
3. Если работа уже идёт, сначала сохрани изменения. Новые инструкции можно прочитать без переключения через `git show <team-remote>/main:AGENTS.md` и аналогично для docs. Скачивания моделей ради этого не останавливай.
4. Если desktop-разработчик уже работал в `codex/android-app`, сохрани там коммит и создай `codex/desktop-app` с сохранением нужной работы. Затем интегрируй актуальный main; не применяй reset/clean или force push.
5. Добавляй в коммит конкретные файлы своей роли. После проверки отправь свою ветку в официальный remote и передай координатору SHA, проверки и блокеры. main самостоятельно не объединяй.
6. Изменения общих схем, API, базовых зависимостей и README предлагает их владельцу — Medet.

Одна репа не означает общую автоматически обновляемую папку. Чужая работа появляется локально после fetch и интеграции нужной ветки. Разделение файлов уменьшает конфликты, а совместимость проверяется при объединении.

## Параллельная работа

- Local AI продолжает настройку на своём компьютере и реализует `local.py` по существующим `base.py`. Конструкторы, версии и параметры записывает в `docs/local-ai/handoff.md`. Подключение адаптеров выполняет backend.
- AI-зависимости фиксируются в `backend/requirements-ai.txt`. Общий план уже допускает pyannote 4.x; не устанавливай устаревший constraint <4.0 из старой ветки. Для каркаса API есть отдельный `backend/requirements-api.txt`.
- Desktop-разработчик использует [API-контракт](api-contract.md) и [синтетический пример](../samples/api/meeting-completed.json). Один API-клиент поддерживает реальный сервер и явно включаемый деморежим.
- API при переходе к EXE сохраняет маршруты и поля. Backend и UI развиваются параллельно; не ждать завершения всех скачиваний для работы над своей частью.

## Размещение и сборка

Backend и модели при первой интеграции работают на компьютере Local AI. EXE запускается на том же ПК либо на другом Windows-компьютере в LAN. Для того же ПК адрес — `http://127.0.0.1:8000`; для другого — согласованный LAN-адрес сервера. Ollama остаётся на loopback сервера, UI не обращается к нему напрямую.

Первый EXE содержит клиентский runtime; Python и модели устанавливаются отдельно на сервере. EXE должен работать без Node.js, npm и dev-сервера на компьютере пользователя. Не выдавать клиентскую сборку за комплект со встроенным AI.

Desktop: сначала проверить упаковку существующего Streamlit UI через pywebview + PyInstaller на Windows. Launcher сам поднимает UI на loopback, дожидается готовности, открывает окно и завершает только свой дочерний процесс при закрытии. Учесть конфликты портов, включение ресурсов/hidden imports и системный WebView2. Зависимости клиента держать отдельно от тяжёлых AI-зависимостей. Готовая клиентская сборка не требует установленного Python.

Если упаковка непрактична, описать измеренный блокер и согласовать Electron + React + TypeScript с координатором. Для этого варианта сохранять contextIsolation и проверяемый main/preload API; не отключать webSecurity ради запросов.

Для LAN-демо адрес и доступ согласуются при интеграции; публичные туннели не требуются. Промышленный доступ требует HTTPS и аутентификации. Подробности подключения описать в handoff.

## Критерии передачи

**Local AI — `docs/local-ai/handoff.md`:** ОС, железо, версии, модели/ревизии, команды, параметры адаптеров, измеренные время и память, проверки mixed ru/kk и оставшиеся ограничения. Токены и чувствительные записи не включать.

**Desktop — `docs/desktop/handoff.md`:** стек и версии, команды запуска и сборки, путь к EXE, SHA-256, архитектура Windows, формат installer/portable, наличие подписи, настройка backend URL, проверки установленной сборки и реальные скриншоты. Если portable-версия требует соседних файлов, перечислить их; не передавать один неработающий EXE из unpacked-папки.

**Backend:** интеграция адаптеров, проверка API и полного сценария: EXE → выбор записи → загрузка → состояния → транскрипт/summary/поручения → DOCX/PDF.

EXE и ключи подписи не хранятся в Git. Артефакт можно приложить к согласованному Release. Скриншоты — `docs/screenshots/`, без персональных данных, с видимой пометкой деморежима при его использовании. Medet обновляет README со ссылкой на проверенную сборку и скриншотами по мере появления результатов. Требования сдачи — [hackathon-checklist.md](hackathon-checklist.md).
