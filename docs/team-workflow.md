# Работа команды из трёх человек

## Ответственность

| Участник | Ветка | Результат | Изменяемые пути |
| --- | --- | --- | --- |
| Medet: backend и интеграция | `codex/backend` | HTTP API, очередь, хранение, объединение STT/diarization, DOCX/PDF | `backend/`, кроме файлов Local AI; общая документация и конфиги |
| Друг: локальные модели | `codex/local-ai-setup` | проверенное окружение, модели, адаптеры существующих интерфейсов | `scripts/local-ai/`, `docs/local-ai/`, `backend/requirements-ai.txt`, `backend/app/services/{stt,diarization,llm}/local.py`, `backend/tests/local_ai/` |
| Друг: Android | `codex/android-app` | мобильный UI, API-клиент, устанавливаемый APK | `mobile/`, `docs/mobile/`, `docs/screenshots/` |

Каждый работает в своей локальной копии и своей ветке одного репозитория. GitHub не синхронизирует открытые папки автоматически. Изменения становятся доступны другим после commit/push, а в их локальных копиях — после fetch и интеграции нужной ветки.

## Старт и синхронизация

1. Проверь `git status`, текущую ветку и `git remote -v`. Выбери remote с URL официального репозитория BAITC-Hacks, не полагайся на имя `origin`.
2. Получи свежие данные через `git fetch <team-remote>`. Для новой работы создай свою ветку от `<team-remote>/main`.
3. Если работа уже началась, сохрани её в своей ветке. Не прерывай скачивание моделей ради смены ветки. При грязном рабочем дереве актуальные инструкции можно сначала прочитать через `git show <team-remote>/main:AGENTS.md` и аналогично для docs.
4. Перед интеграцией main сохрани свои изменения. Подтяни main в рабочую ветку обычным merge. Если конфликт затрагивает общие схемы или чужой код, согласуй решение с владельцем.
5. Добавляй в коммит конкретные файлы своей задачи, проверь staged diff и отсутствие секретов/моделей. Отправляй явно свою ветку в официальный remote, без force push.
6. Передай координатору имя ветки, SHA коммита, результат проверок и блокеры. PR удобен для проверки, но не заменяет согласование контракта. Самостоятельно main не объединяй.

Разделение файлов уменьшает вероятность конфликтов, но совместимость всё равно проверяется при интеграции. Общий API описан в [api-contract.md](api-contract.md). Его изменения координирует backend; мобильный разработчик не придумывает параллельные поля и URL.

## Параллельная работа

- Local AI продолжает установку на своём компьютере, затем добавляет конкретные реализации в `local.py`, наследуя существующие `base.py`. Конструкторы и параметры опиши в `docs/local-ai/handoff.md`; подключение в backend выполняет Medet.
- Python AI-зависимости фиксируются отдельно в `backend/requirements-ai.txt`. Не ставь слепо старый общий requirements с ограничением pyannote <4.0: координатор исправит общий файл до объединения. Не создавай второй независимый HTTP-сервер.
- Android-разработчик начинает с [API-контракта](api-contract.md) и [синтетического ответа](../samples/api/meeting-completed.json). Один API-клиент должен поддерживать реальный сервер и явно включаемый деморежим.
- Все три части дорабатываются параллельно. Backend не ждёт окончания скачиваний, Android не ждёт настоящих моделей.

## Где работает продукт

Для первой интеграции backend и модели запускаются на компьютере участника Local AI. APK обращается только к backend по его доступному адресу в локальной сети. Ollama остаётся на loopback этого компьютера; телефон напрямую к Ollama не подключается.

В настройках APK пользователь вводит адрес backend. `localhost` на физическом телефоне означает сам телефон. Сервер и телефон должны иметь сетевой доступ друг к другу; гостевая сеть хакатона может изолировать устройства. Адрес, интерфейс прослушивания и необходимый доступ согласуются при интеграции; публичные туннели и открытие сети целиком не требуются.

Для LAN-демо HTTP допускается только в явно документированной конфигурации тестовой сборки. Production-вариант потребует HTTPS и контроля доступа. APK должен явно показывать недоступность backend, а не подменять результат демоданными.

## Передача и критерии готовности

**Local AI — `docs/local-ai/handoff.md`:** железо и ОС, версии, модели/ревизии, пути без секретов, команды установки/запуска, интерфейсы адаптеров, измеренное время и память, какие тесты прошли, ограничения mixed ru/kk, что требуется backend. Доступ к gated-модели и условия Hugging Face владелец аккаунта оформляет сам.

**Android — `docs/mobile/handoff.md`:** стек и версии, команды сборки, путь к APK и SHA-256, способ установки, настройка API URL, что проверено на устройстве/эмуляторе, реальные скриншоты и ограничения. Сборка должна запускаться без Expo Go и Metro. AI-обработка требует доступного backend.

**Backend:** после объединения проверяет весь сценарий: установка APK → выбор записи → загрузка → состояние обработки → транскрипт/summary/поручения → скачивание DOCX/PDF. Неизвестные имена и сроки не выдумываются.

APK и ключи подписи не хранятся в истории Git. APK можно позднее приложить к согласованному GitHub Release. Скриншоты сохраняются в `docs/screenshots/` без персональных данных, с обозначением деморежима, если он включён. README со скриншотами и ссылкой на проверенную сборку обновляет Medet после передачи результатов.
