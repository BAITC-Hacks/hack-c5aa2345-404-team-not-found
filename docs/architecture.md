# Архитектура SAMRUK KAZYNA

## Цель MVP

Локально обработать запись совещания из Windows-приложения и вернуть транскрипт с анонимными говорящими, summary, поручения и DOCX/PDF. Клиент поставляется как EXE. Приоритет — сохранить Streamlit UI из ветки codex/streamlit-frontend и проверить упаковку через pywebview + PyInstaller; совместимость и сборка ещё не подтверждены. Интеграции с Teams, Zoom, Google Meet и напоминания остаются за пределами текущего MVP.

Распределение работы: [team-workflow.md](team-workflow.md). Граница Desktop/backend: [api-contract.md](api-contract.md); описанные новые методы ещё предстоит реализовать.

## Целевой поток данных

```text
Windows EXE: выбор audio/video
    -> FastAPI backend на том же ПК или в LAN (загрузка, очередь, хранение)
    -> FFmpeg preprocessing
    -> local STT (faster-whisper)
    -> local diarization (pyannote)
    -> merge by timestamps
    -> local LLM (Ollama or llama.cpp)
    -> transcript + summary + tasks
    -> DOCX/PDF protocol
```

Каждый этап работает внутри инфраструктуры заказчика. Аудио, транскрипт, промпты и результаты не отправляются в OpenAI, Google, Anthropic и другие внешние AI API.

При первой интеграции backend и модели размещаются на компьютере участника Local AI. Windows-клиент может работать на нём же или на другом ПК в LAN. Клиент обращается только к backend; Ollama остаётся на loopback сервера. При ограниченной видеопамяти этапы запускаются последовательно с освобождением моделей. Код адаптеров готовит Local AI; управление заданиями, объединение timestamps и подключение адаптеров — backend.

Первый EXE содержит клиентский интерфейс и его runtime. Python backend и модели устанавливаются отдельно; комплект «всё в одном» пока не реализуется. Сборка должна запускаться без Node.js и dev-сервера на машине пользователя, показывая состояние подключения к backend. Статус разработки и команды запуска — в корневом README.

В варианте Streamlit упакованный launcher сам запускает локальный UI-сервис на loopback, показывает его в окне pywebview и завершает свой дочерний процесс при закрытии. Пользователь не должен вручную запускать Streamlit или устанавливать Python для клиента. Статические ресурсы UI и зависимости включаются в сборку; необходимость системного WebView2 фиксируется в инструкции. Изменения backend в исходной UI-ветке рассматриваются отдельно: [integration-notes.md](integration-notes.md).

## Смешанная речь

Ключевой критерий качества — сохранение исходных казахских, русских и английских технических слов в одной реплике. Система не должна принудительно переводить или нормализовать весь текст в один язык. Проверка на шала-қазақша входит в план оценки STT.

## Безопасность

- исходные записи и результаты хранятся локально и исключены из Git;
- чувствительные данные и токены размещаются только в локальном `.env`;
- перед загрузкой файлов будет добавлена проверка формата, размера и безопасного имени;
- до появления аутентификации доступ к API не считается production-ready;
- удаление исходной записи после обработки должно стать настройкой deployment.

## Будущая инфраструктура

MVP: Python/FastAPI + локальная файловая система + SQLite. После проверки сценария: Docker Compose, PostgreSQL и развёртывание в закрытом контуре. Точные модели, GPU-профиль и параметры inference будут выбраны после замеров на согласованных тестовых записях.
