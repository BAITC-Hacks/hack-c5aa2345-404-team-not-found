# SAMRUK KAZYNA — нативное Windows-приложение

Самостоятельный **C# / Windows Forms EXE**. Основной код — `desktop/native/`,
сборка — `desktop/build-native.ps1`. Прежние Streamlit UI и эксперимент
pywebview/PyInstaller сохранены отдельно и не входят в этот клиент.

Клиент помогает секретарю просмотреть резюме, проверить поручения по исходным
репликам и сохранить протокол. Его целевой источник данных — локальный backend,
который должен обрабатывать русские, казахские и смешанные записи. Экономия
времени и качество извлечения поручений пока не измерены.

**Статус по отчёту Windows Desktop от 23.09.2026:** EXE был собран и запущен;
в GUI проверены демопротокол RU/KK, выбор файла, сохранение DOCX и закрытие;
сообщено о 21/21 native-проверках. Эти результаты и точная среда приведены в
[handoff.md](handoff.md). При текущем документировании сборки и тесты не
повторялись. Backend теперь реализует все маршруты, очередь, хранение и локальный
DOCX/PDF. Пройдены 22 backend-, 43 Local AI-проверки и 10 проверок native-клиента
с настоящим API и подменёнными моделями. Сквозной GPU-сценарий с настоящими
моделями и записью ещё требуется подтвердить. Запуск — [backend-launch.md](../backend-launch.md).

## Что реализовано в исходниках

| Возможность | Поведение текущего клиента |
| --- | --- |
| Окно и навигация | «Новое совещание», «История протоколов», «Подключение»; нативные WinForms-контролы |
| Запись | файловый диалог WAV/MP3/M4A/MP4, непустой файл до 500 МиБ, необязательное название |
| Сетевой сценарий | загрузка, опрос состояния примерно раз в 2 секунды, получение результата и экспорта по целевому API |
| Ожидание | название стадии и движущийся индикатор без выдуманного процента; кнопка прекращает ожидание клиента |
| Протокол | резюме; реплики с говорящим и временем; поручения, ответственный, срок, кто поручил и исходная реплика |
| История | список с backend; открытие завершённой встречи; незавершённые нужно обновлять кнопкой списка |
| Демо | встроенный синтетический JSON, явная пометка в окне и локальном DOCX; не отправляется в историю backend |
| Экспорт | локальный DOCX для демо; для реальных результатов — только форматы, объявленные backend; отдельный системный диалог печати |

Сетевой сценарий реализован в клиенте и backend. Готовность локальных моделей
проверяется через health. `Остановить ожидание` не отменяет серверную задачу: после
прерывания загрузки сначала проверьте историю, чтобы не создать дубликат.
В native-клиенте нет редактирования поручений, KPI-дашборда, переключения темы
или подключения к Teams/Zoom/Google Meet. Возможности отдельного Streamlit-демо
описаны в [его инструкции](../../frontend/README.md).

## Требования и артефакт

- Windows с **.NET Framework 4.8 или новее**.
- Машина из отчёта предыдущей проверки: **Windows 11 build 22631, .NET Framework 4.8.1, Release 533320**.
- Python, Node.js, WebView2, браузер, UI-сервер и `_internal` клиенту не нужны.
- Backend и модели устанавливаются отдельно на этом же ПК либо на сервере в LAN.
- EXE не подписан. На другом компьютере запуск ещё не проверен.

Команда сборки создаёт `desktop/release/SAMRUK-KAZYNA.exe` и файл его SHA-256.
**В чистом клоне готового EXE нет:** `desktop/release/`, бинарники и результаты
проверок исключены из Git. Соберите клиент либо получите артефакт у команды.

Справочные значения из отчёта Desktop от 23.09.2026: **88 064 байта**, SHA-256:

```text
07484cbd2202608f870c2ee782a623af579f2732ec68ec7b54a231ab04ecee57
```

Это идентификатор описанного исторического артефакта, а не обещание того же
хеша после новой компиляции. Новая сборка записывает собственный хеш в
`desktop/release/SAMRUK-KAZYNA.exe.sha256`. По прежнему отчёту отдельная копия
EXE запускалась на той же машине из временной рабочей папки. Проверка на другом
или чистом ПК не выполнялась; там может потребоваться установка .NET Framework.

## Сборка и запуск

Из корня репозитория в PowerShell:

```powershell
.\desktop\build-native.ps1
.\desktop\release\SAMRUK-KAZYNA.exe
Get-FileHash .\desktop\release\SAMRUK-KAZYNA.exe -Algorithm SHA256
```

Скрипт использует системный `csc` (.NET Framework), C# 5, Windows Forms и платформу
AnyCPU. Демопример встроен в EXE. На машине пользователя можно запустить один
`SAMRUK-KAZYNA.exe` двойным щелчком; приложение открывает собственное Windows-окно.
Для сборки нужен компилятор, для запуска — только соответствующий .NET Framework.
Скрипт ищет `csc.exe` в системных каталогах .NET Framework64/Framework
`v4.0.30319`; если его нет, сообщает о необходимости .NET Framework 4.8 Developer
Pack. Сборка не устанавливает пакеты и не скачивает модели.

`desktop/build.ps1` — короткая обёртка этой же native-сборки. Старый эксперимент
сохранён в `desktop/build-webview-experiment.ps1`, `launcher.py`, `package.py`
и `SAMRUK-KAZYNA.spec`. Они не нужны для native-сборки. `desktop/requirements-*.txt`
относятся к прежней Python/Qt-упаковке, а не к зависимостям C#-клиента.

## Подключение к backend

На странице **«Подключение»** задайте адрес:

- `http://127.0.0.1:8000` — сервер на этом же ПК;
- `http://<server-lan-ip>:8000` — согласованный адрес ПК Local AI.

Принимается HTTP(S)-адрес сервера, при необходимости с портом: без `/api`, логина, токена,
query-параметров и фрагмента. Настройка хранится в
`%LOCALAPPDATA%/SAMRUK_KAZYNA/native-settings.json`. До первого сохранения
используется `MEETING_API_URL`, иначе localhost; сохранённый адрес имеет приоритет.
По предыдущему GUI-отчёту сохранение адреса и сообщение о недоступном backend
проверены. Восстановление значения после перезапуска отдельно не проверялось.
Технический журнал необработанных исключений —
`%LOCALAPPDATA%/SAMRUK_KAZYNA/native.log`; код записывает тип исключения, а не запись
совещания или транскрипт.

Backend должен работать отдельно и быть доступен по сети. Клиент не запускает
Ollama и модели. `status=ok` означает готовность по предварительным проверкам;
`status=not_ready` — отсутствующие или недоступные зависимости. При неготовности
загрузка возвращает HTTP 503. Ошибка соединения не заменяется демонстрационным
результатом. Команды запуска — [инструкция backend](../backend-launch.md).

## Демонстрация и экспорт

1. Соберите и запустите EXE. При выключенном backend ожидается сообщение о его
   недоступности; интерфейс остаётся доступным.
2. Нажмите **«Открыть демо»**. Должна появиться пометка **«ДЕМО · синтетические данные»**.
3. Просмотрите резюме, русский/казахский транскрипт с говорящими и временными
   метками, поручения и их источники.
4. Нажмите **DOCX**, выберите папку и откройте сохранённый документ. В нём должны
   быть резюме, поручение с источником, транскрипт и пометка DEMO.
5. Откройте **«Подключение»**, сохраните адрес запущенного backend
   `http://127.0.0.1:8000` и нажмите **«Проверить связь»**. Проверьте `ok` либо
   `not_ready`; команды настройки — в [инструкции backend](../backend-launch.md).
6. Выберите разрешённый синтетический WAV и нажмите **«Начать обработку»**.
   При `not_ready` обработка недоступна и сервер отклоняет загрузку с HTTP 503.
   При `ok` ожидаются очередь, стадии обработки и результат либо явная ошибка.
   Синтетическая запись проверяет интерфейс; качество речи требует отдельной
   согласованной записи и ручной сверки результата.
7. Закройте окно; сервер backend, запущенный отдельно, продолжает работать.

Демо синтетическое. Выбор записи через файловый диалог не означает её
распознавание. Таблица поручений **только для просмотра**: редактирование и
сохранение задач не реализованы, соответствующего метода нет в API-контракте.

**DOCX демо** создаётся автономно; его проверка описана в предыдущем handoff. Для реального результата DOCX/PDF
скачиваются через backend. Автономный PDF доступен только через системную печать
в PDF, если установлен PDF-принтер, например Microsoft Print to PDF.
**Печать и сохранение через PDF-принтер пока не проверены.**

## Целевой API

Native-клиент следует [контракту](../api-contract.md):

| Действие | Метод |
| --- | --- |
| Health | `GET /health` |
| Загрузка | `POST /api/meetings`, multipart `file`, необязательный `title` |
| Список | `GET /api/meetings`, ответ `items` |
| Состояние | `GET /api/meetings/{id}` |
| Результат | `GET /api/meetings/{id}/result` |
| Экспорт | `GET /api/meetings/{id}/export?format=docx` или `pdf` |

По предыдущему handoff запросы и обработка ответов проверены с локальным тестовым сервером.
Теперь все перечисленные серверные маршруты реализованы. Дополнительно пройдены
10 проверок native-клиента с настоящим API, очередью и экспортом при подменённых
моделях. Эти проверки не подтверждают сквозной GPU-запуск настоящих моделей.

## Выполненные проверки и следующий шаг

В предыдущем handoff указаны **21/21** native-проверки. Для самостоятельного
повторения после сборки на Windows x64 с Python 3.11 и системным `Framework64/csc`:

```powershell
py -3.11 .\desktop\tests\run-native-checks.py
```

Python нужен только для этого тестового сценария. Он компилирует проверяющую
программу, использует уже собранный EXE и локальный HTTP fixture. Модели не
запускаются; аудио во внешние сервисы не отправляется. Сторонние Python-пакеты
для этого сценария не нужны. Отчёты появятся в
`desktop/build/native-tests/checks.json` и `fixture.json`. Ожидается
`passed=true`, `checks=21`, `failures=0`; PDF в HTTP fixture — синтетические
байты для проверки транспорта, а не проверка вёрстки готового PDF.

По GUI-отчёту Desktop отдельно наблюдались запуск окна, RU/KK-демо, системный выбор `synthetic.wav`,
сохранение `desktop/build/native-gui-check/SAMRUK-DEMO.docx` и завершение процесса
после закрытия. Реальные [транскрипт](../screenshots/native-demo-transcript.png)
и [поручения](../screenshots/native-demo-tasks.png) сняты с запущенного приложения.
Также сохранён [summary с пометкой DEMO](../screenshots/native-demo-summary.png).
Эти снимки показывают синтетический пример и отключённый backend; сами по себе
они не подтверждают распознавание аудио, качество модели или сквозную интеграцию.

Страница [настроек подключения](../screenshots/native-settings.png) также снята
с запущенного приложения. Копия только EXE успешно запущена отдельно от каталога
сборки, с временной рабочей директорией.

Осталось проверить загрузку настроек после перезапуска, другой Windows-ПК, печать, а затем
полный сценарий с сервером Local AI и настоящей записью. Предыдущие 14
Streamlit-тестов относятся к сохранённому веб-прототипу, не включены в 21
native-проверку. Бинарник и модели не добавляются в Git; Release согласуется отдельно.
