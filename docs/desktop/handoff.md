# Передача native EXE SAMRUK KAZYNA

Дата: 2026-09-23. Ветка: `codex/desktop-app`.

**Источник сведений:** ниже сохранён отчёт участника Windows Desktop от
23.09.2026 о выполненных им сборке, проверках и GUI-наблюдениях. При аудите
документации текущего `main` исходники, команды и сохранённые скриншоты были
просмотрены статически; сборка, приложение и тесты заново не запускались.
Счётчики проверок, сведения о машине и хеш относятся к предыдущему отчёту,
не являются новым результатом аудита и не доказывают работу AI-пайплайна.

**Результат по этому отчёту:** нативный клиент C# 5 / Windows Forms собран и запущен.
На финальной сборке прошли **21/21 native-проверки**; в GUI проверены
демопротокол, системный выбор файла, автономный DOCX и завершение процесса.
Backend и реальные модели не интегрированы: активный API остаётся scaffold/501.

## Воспроизведение

Из корня репозитория:

```powershell
.\desktop\build-native.ps1
.\desktop\release\SAMRUK-KAZYNA.exe
Get-FileHash .\desktop\release\SAMRUK-KAZYNA.exe -Algorithm SHA256
```

Исходники — `desktop/native/`. Backend и AI-модели устанавливаются отдельно на
сервере, они не встроены в клиент. Пользовательский адрес API сохраняется в
`%LOCALAPPDATA%/SAMRUK_KAZYNA/native-settings.json`.

## 21 native-проверка

Команда разработчика:

```powershell
py -3.11 .\desktop\tests\run-native-checks.py
```

Сценарий проверяет код финального собранного EXE через C# harness и локальный
HTTP fixture. Для повторения нужны предварительная native-сборка, Python,
Windows x64 и системный `Framework64/v4.0.30319/csc.exe`; GUI он не открывает.
В предыдущей проверке локальный отчёт `desktop/build/native-tests/checks.json` содержал:
`passed=true`, `checks=21`, `failures=0`. Это проверка с синтетическими данными,
не тест производственного backend или AI-моделей.

| Группа | Подтверждённое поведение |
| --- | --- |
| URL | нормализация origin; отклонение секретов и адресов с путём |
| Демо | встроенный JSON читается и сохраняет казахские символы |
| DOCX | ZIP/XML, RU/KK, источники поручений, пометка DEMO, atomic overwrite, очистка некорректных XML-символов |
| Целевой API | health, список `items`, multipart `file`/`title`, Meeting, Result, DOCX/PDF routes |
| Ошибки | scaffold 501, validation 422 без повторения входных секретов, некорректный JSON |
| Валидация результата | несовпадение ID, неверные timestamps, нелокальный результат, слишком большой JSON, неверный экспорт |
| Сеть | redirect POST отклоняется без повтора; отмена прерывает чтение ответа |

Fixture-отчёт подтверждает одну обычную загрузку, один отклонённый redirect и
**ноль запросов к адресу перенаправления**. Multipart содержит `file`, а не
legacy `audio`; имя, байты и UTF-8 title сохранены.
Эти утверждения относятся к сохранённому отчёту запуска. PDF fixture содержит
синтетический заголовок `%PDF-`, поэтому проверка маршрута и сигнатуры не
подтверждает отображение или качество настоящего серверного PDF.

## Ограничения и непроверенные сценарии

1. Активный backend возвращает `status=scaffold` и 501 на загрузку. Очередь,
   реальные модели и серверный экспорт ещё не проверены с EXE.
2. Таблица поручений доступна **только для просмотра**. Редактирование и
   сохранение задач не реализованы; соответствующего метода нет в API-контракте.
3. Автономный демоэкспорт DOCX работает. Реальные DOCX/PDF запрашиваются через
   backend. Демонстрационный PDF возможен через Windows print-to-PDF при
   установленном PDF-принтере; **печать не проверена**.
4. Сохранение настроек проверено через GUI; восстановление значения после
   перезапуска отдельно не проверялось.
5. На другом компьютере, включая чистую Windows без средств разработки, EXE
   не запускался. Совместимость ограничена описанной проверенной машиной.
6. EXE не подписан. GitHub Release не опубликован.
7. В native-клиенте нет KPI-дашборда, переключения темы, редактирования поручений
   и подключения к онлайн-конференции. История открывает только завершённые
   встречи; состояния queued/processing обновляются вручную через список.
   Кнопка «Остановить ожидание» отменяет ожидание HTTP на клиенте, а не задачу
   на backend. При неопределённом результате загрузки сначала проверьте историю.

Первую серверную интеграцию выполняем с ПК участника Local AI:
`http://127.0.0.1:8000` для того же ПК либо согласованный LAN-адрес для другого.
Клиент использует целевой `docs/api-contract.md`, не legacy маршруты Streamlit.

## Отдельный результат прежнего UI

`frontend/` сохранён из main merge `7f341e8`. Его предыдущие **14/14** тестов
(`test_desktop_settings.py` 7, `test_frontend_state.py` 4,
`test_meeting_editor.py` 3) относятся к Streamlit. Они не включены в 21 native
проверку и не служат подтверждением WinForms-клиента.
Это отдельный отчёт набора **7 settings + 4 frontend state + 3 meeting editor**.
Не объединяйте его с более ранним счётчиком 14 проверок Streamlit/backend,
где семь проверок относились к прежнему backend, и не считайте одинаковое
число доказательством актуальности всех тестов репозитория.

`desktop/build.ps1` теперь вызывает основную `desktop/build-native.ps1`.
Эксперимент pywebview/Qt/PyInstaller сохранён отдельно в
`desktop/build-webview-experiment.ps1`. По предыдущему локальному отчёту его
архив перенесли в `desktop/build/abandoned-webview/`; эти игнорируемые артефакты
не поставляются с репозиторием. Текущая native-сборка создаёт EXE и sidecar в
`desktop/release/`; экспериментальный `package.py` к ней не относится.
