# Проверка решения для жюри

## Что вы оцениваете

SAMRUK KAZYNA помогает превращать русско-казахские совещания в протоколы
с проверяемыми поручениями. Участники команды реализовали нативный Windows-клиент
и backend с очередью, хранением, локальными AI-адаптерами и DOCX/PDF. Связь native
API-клиента с настоящим backend проверена на синтетических ответах моделей;
проверка всего продукта на реальной записи ожидается на компьютере Local AI.

Можно отдельно проверить интерфейс с синтетическим примером, HTTP-интеграцию и
полный сценарий на готовом сервере моделей. Успех демонстрации интерфейса не
подтверждает качество распознавания речи.

## 1. Подготовка

1. Получите доступ к репозиторию и клонируйте его по [README](../README.md).
2. Запишите `git rev-parse HEAD` — результат проверки относится к этому коду.
3. Для клиента используйте Windows и .NET Framework 4.8+. Соберите EXE командой
   `.\desktop\build-native.ps1` из корня репозитория.
4. Запишите SHA-256 полученного EXE. Не сравнивайте его автоматически с хешем
   старой сборки: побайтовая воспроизводимость сборок не подтверждена.

Готовый EXE не входит в clone. Release пока не опубликован. Подробности сборки
и запуска: [Desktop README](desktop/README.md).

## 2. Доступный сценарий интерфейса

Запустите `.\desktop\release\SAMRUK-KAZYNA.exe`.

| Шаг | Ожидаемый результат | Что это подтверждает |
| --- | --- | --- |
| Нажмите «Открыть демо» | Видна пометка синтетических данных | Демо включается явно |
| Откройте резюме | Краткий текст о подготовке отчёта | Отображение summary |
| Откройте транскрипт | Две RU/KK-реплики, говорящие и timestamps | Корректное отображение языков и структуры |
| Откройте поручения | Подготовка отчёта, Айдос, относительный срок и цитата | Проверяемая структура поручения |
| Нажмите «DOCX», сохраните и откройте файл | Протокол содержит DEMO, текст и поручение | Автономный экспорт демо в DOCX |
| Откройте «Подключение» | Адрес backend можно задать и проверить | Настройки сетевого клиента |

Демопример встроен при сборке из
[`samples/api/meeting-completed.json`](../samples/api/meeting-completed.json).
Выбор файла записи через диалог и открытие демо не означают распознавание этого файла.
Таблица поручений только для чтения. «PDF» предназначен для серверного экспорта;
«Печать / PDF» использует системную печать, которая ещё не подтверждена отчётом.

## 3. Проверка состояния backend

Запустите API по [инструкции сервера моделей](backend-launch.md). В настройках EXE
укажите `http://127.0.0.1:8000`, если он работает на том же ПК.

| Запрос / действие | Ожидание для текущего main |
| --- | --- |
| `GET /health` | HTTP 200, `local_only=true`; `status=ok` при доступных ресурсах, иначе `not_ready` |
| Открыть `/docs` | Swagger показывает загрузку, список, состояние, результат и экспорт |
| `POST /api/meetings` | При готовности — HTTP 202 и ID; при недоступных ресурсах — 503 |
| Нажать «Начать обработку» в клиенте | При `ok` загружается выбранная запись и начинается опрос состояния; при `not_ready` клиент сообщает о неготовности |
| Запросить историю | `GET /api/meetings` возвращает `items` из SQLite |
| Получить результат/экспорт | После `completed` доступны Result и DOCX/PDF; до готовности — 409 |

Backend сохраняет принятую запись локально и обрабатывает её одним worker:
FFmpeg → STT → диаризация → анализ → экспорт. Статусы: `queued`, `processing`,
`completed` или `failed`. Недоступный backend не включает деморежим автоматически.
На ПК Medet запуск без подмен вернул ожидаемый `not_ready`, поскольку модели
установлены на другом компьютере. Успешный health проверяет наличие ресурсов,
но ещё не доказывает правильность обработки записи.

## 4. Технические проверки компонентов

- [Native-проверки](verification.md) используют временный HTTP-сервер и синтетические
  ответы: их можно воспроизвести отдельно от моделей.
- Отдельная проверка native API-клиента с настоящими FastAPI, SQLite, worker и
  экспортом прошла 10/10; модели и FFmpeg в ней заменены синтетическими вызовами.
- Backend и алгоритмы pipeline прошли 22/22 проверки; серверный PDF проверен
  по извлечённому RU/KK-тексту и отрисованному изображению.
- [Local AI](local-ai/README.md) описывает установку и прямой запуск Whisper,
  Community-1 и Qwen3. Для записи требуется согласие на её использование.
- [Отчёт моделей](local-ai/handoff.md) содержит прежние измерения и известные ошибки.

В репозитории нет общедоступной эталонной аудиовыборки. JSON из `samples/` —
синтетический пример контракта, а не эталон измерения WER или DER.

## 5. Приёмка на готовом сервере моделей

Код сценария реализован. Следующая проверка с настоящими моделями и записью
ещё должна быть выполнена на компьютере участника Local AI:

1. Загрузить согласованную запись через EXE; получить ID встречи.
2. Наблюдать состояния очереди и обработки; получить реальный Result.
3. Сверить текст с аудио, затем timestamps и разделение говорящих.
4. Сверить каждое поручение, ответственного, срок, автора и цитату.
5. Убедиться, что неизвестные данные не заменены догадками.
6. Скачать DOCX/PDF и сверить их с показанным результатом.
7. Повторить после отключения внешнего интернета с доступным LAN-backend.
8. Записать версию кода и моделей, длительность записи, время и память,
   ошибки и условия проверки. Эталонный транскрипт нужен для метрик качества.

## Форма фиксации результата

Сохраните локально: commit SHA, Windows/.NET/Python, модель и revision, SHA-256 EXE,
проверенные шаги, ожидаемый/фактический результат, длительность и ограничения.
Не публикуйте реальные аудио, транскрипты и персональные данные в Git.
