# Промпты команды SAMRUK KAZYNA

Текущая платформа — **Windows EXE**. Этот документ заменяет предыдущую Android/APK-задачу. Отправь соответствующий промпт в существующую сессию друга; изменение GitHub само по себе не меняет задание в уже работающей сессии.

## Участник Local AI — продолжение установки

```text
Продолжай текущую установку моделей, сохрани загрузки и прогресс. Название проекта теперь SAMRUK KAZYNA; клиент будет Windows EXE. Нас трое: Medet делает backend и интеграцию; ты — Local AI; третий участник — Desktop UI и EXE.

Официальный репозиторий:
https://github.com/BAITC-Hacks/hack-c5aa2345-404-team-not-found

Получай актуальный main через fetch и прочитай AGENTS.md, README.md, docs/team-workflow.md, docs/api-contract.md и base.py в backend/app/services. При незавершённых изменениях сначала сохрани работу; инструкции можно читать через git show <team-remote>/main:<path>. Remote выбирай по URL, не по предположению об имени origin.

Работай в codex/local-ai-setup. Установка и скачивание моделей разрешены предыдущим заданием. Определи железо и настрой faster-whisper/Whisper, pyannote Community-1 и локальную Qwen3 через Ollama. Сверяй официальные требования. Community-1 требует совместимого pyannote.audio 4.x; на Windows проверь TorchCodec и FFmpeg shared DLL. Отключи облачные функции Ollama и необязательную телеметрию pyannote. Условия Hugging Face и токен оформляет владелец аккаунта; секреты не выводи.

Твои пути: scripts/local-ai/, docs/local-ai/, backend/requirements-ai.txt, backend/tests/local_ai/, backend/app/services/{stt,diarization,llm}/local.py. Реализуй адаптеры существующих base.py. Загрузка моделей должна быть явной, а не побочным эффектом импорта. Общие схемы, API, __init__.py, README и desktop-код не переписывай; необходимые изменения предложи Medet.

Backend и модели будут работать на твоём ПК; EXE-клиент может работать там же либо на другом ПК в LAN. Новый отдельный сервер для моделей не создавай. Ollama оставь на loopback; очередь, объединение timestamps и экспорт делает Medet.

Проверь модели на согласованной русско-казахской записи без чувствительных данных. Если записи нет, попроси её и продолжай независимые проверки. Ограниченную видеопамять учитывай последовательным запуском и освобождением моделей. Подтверди локальную обработку после скачивания, не отправляй аудио и текст во внешние сервисы.

В docs/local-ai/handoff.md запиши железо, версии, модели/ревизии, команды установки и запуска, параметры адаптеров, реальные результаты и ограничения. Жюри должны воспроизвести запуск по этим сведениям. Токены, .env, модели, записи и окружения в Git не добавляй.

Разрешаю коммит и push файлов своей роли в codex/local-ai-setup после проверок. Это сохраняет ранее выданное разрешение на отправку своей ветки. В main не сливай, force push не используй. Передай SHA, проверки и блокеры.
```

## Участник Windows Desktop EXE

```text
Обновление задания: делаем SAMRUK KAZYNA для Windows, итоговый артефакт — EXE. Предыдущая задача Android/APK отменена. Сохрани уже сделанную работу в прежней ветке и используй пригодные наработки без удаления истории.

Репозиторий:
https://github.com/BAITC-Hacks/hack-c5aa2345-404-team-not-found

Medet отвечает за backend/API и интеграцию, другой участник — за локальные модели, ты — за Windows-приложение. Получи свежий main и прочитай AGENTS.md, README.md, docs/team-workflow.md, docs/api-contract.md, docs/hackathon-checklist.md и samples/api/meeting-completed.json. Проверяй remote по URL, сохраняй локальные изменения перед интеграцией.

Работай в codex/desktop-app. Твои файлы: frontend/, .streamlit/, desktop/, docs/desktop/, docs/screenshots/. Общие backend-схемы, маршруты, корневой README и конфиги не переписывай. Сначала прочитай docs/integration-notes.md и опубликованную ветку codex/streamlit-frontend: там уже есть UI. Сохрани её историю; backend-изменения из этой ветки передай на отдельную интеграцию Medet, не объединяй весь commit в main автоматически.

Сохрани подходящий существующий Streamlit UI и сначала проверь упаковку Windows EXE через pywebview + PyInstaller; launcher и сборочные настройки положи в desktop/. Launcher должен сам запускать локальный UI на loopback, дождаться готовности, открыть окно и при выходе завершить только свой дочерний процесс. Учти ресурсы Streamlit, hidden imports, занятый порт, закрытие окна и требования WebView2. Зависимости UI отдели от AI-пакетов. Установка нужных инструментов и зависимостей разрешена. Сверь официальную документацию. Если упаковка непрактична, покажи конкретный блокер и согласуй Electron-вариант, сохранив наработки. Название окна и интерфейса — SAMRUK KAZYNA.

Нужен самостоятельный Windows EXE: установщик либо корректный portable-артефакт, работающий без установленного Python/Node.js и ручного запуска UI-сервера на машине пользователя. Python backend и модели устанавливаются отдельно на сервере; не выдавай клиентскую сборку за встроенный AI-комплект. Не загружай облачные AI сервисы. Ключи подписи храни вне Git; если сертификата нет, явно отметь, что сборка не подписана.

Реализуй удобный desktop-интерфейс: список встреч, создание встречи, выбор аудио/видео через диалог или drag-and-drop, загрузку, состояние обработки, резюме, транскрипт с говорящими и временными метками, поручения с источниками, сохранение DOCX/PDF и настройки backend URL. Учти изменение размера окна, клавиатуру, русский и казахский текст, длинные реплики, пустые состояния и ошибки. Сначала заверши загрузку готовой записи; запись микрофона — после основного сценария.

Соблюдай docs/api-contract.md. Пока backend не готов, используй синтетический пример в явно включаемом деморежиме с видимой пометкой. Подготовь настоящий API-клиент; ошибки сервера не подменяй демоданными. Изменения контракта согласуй с Medet.

Адрес по умолчанию для того же ПК — http://127.0.0.1:8000; для другого ПК пользователь задаёт LAN-адрес. Клиент обращается к backend, а не к моделям напрямую. Не предоставляй странице неограниченный Python/Node.js-мост; проверяй адрес backend и параметры операций с файлами. Для Electron-варианта сохраняй contextIsolation, ограниченный IPC и включённый webSecurity. Не открывай произвольные ссылки из транскриптов автоматически.

Проверь типы, сборку, запуск итогового EXE на Windows без dev-сервера, выбор/загрузку файла, отображение результата и сохранение экспорта. Отделяй проверки с демоданными от проверок живого backend. Если среда не позволяет проверить EXE, явно зафиксируй блокер и не называй артефакт проверенным.

Сделай реальные скриншоты запущенной сборки в docs/screenshots/ без персональных данных. В docs/desktop/handoff.md запиши версии, команды установки/разработки/сборки, путь к артефакту, SHA-256, требования Windows, наличие подписи, backend-настройки, проверки и ограничения. Добавь готовые подписи для скриншотов, чтобы Medet обновил README сразу после передачи.

Разрешаю коммит и push файлов своей роли в codex/desktop-app после проверок. В main не сливай, force push не используй. Бинарные сборки, ключи, .env и данные встреч не коммить. Передай EXE как артефакт; публикацию Release согласуем отдельно. Сообщи SHA и результаты, доведи задачу до доступного результата.
```
